## Required contract corrections
1. **P2 — Open can discard a draft.** Contract21/39/50 omit a retention mechanism: `packages/app/src/screens/chat/model-composer.tsx:66–71,86–87` owns text/files locally; `packages/app/src/shell/shell.tsx:82,121` replaces Chat on navigation. Opening an older attachment then Back loses an unsent/refused-send draft, even if the viewer later refuses the image.
   Smallest no-store fix: synchronously guard Open against composer dirty/reading/submitting state, with an accessible localized reason; latch interaction during accepted deferred Open so new typing cannot race unmount, restoring it on canceled Back. Include `model-composer.tsx` in scope. No silent clearing, attachment bytes in history/localStorage or approval dialog.
2. **Pin the allocation claim (contract23–25/41).** Adopt inclusive ceilings of 50,000,000 base64-decoded file bytes, 40,000,000 pixels and 32,768 per positive dimension. File bytes are still compressed image data; they are not decoded RGBA memory.
   `img.decode()`/`createImageBitmap()` return after decode/allocation; checking natural dimensions or bitmap dimensions afterward cannot prevent the oversized allocation. Resize options likewise promise no source-allocation ceiling (`node_modules/typescript/lib/lib.dom.d.ts:846–853,14685,18620–18638`).
   For a pre-decode dimension gate, use one small Files-owned byte/header validator before any image source assignment: PNG IHDR/chunk bounds, JPEG length-delimited SOF dimensions, WebP RIFF plus VP8/VP8L/VP8X dimensions. Reject truncated, inconsistent, unknown-dimension structures; cross-check extended canvas/bitstream dimensions. Native decode must still succeed afterward.
   If header preflight is omitted, these are only post-decode acceptance limits; remove every preventive decode-memory claim. Even with preflight, there is no total renderer/decoder/IPC memory bound: full histories, base64/string copies, multiple thumbnails and decoder overhead remain.
3. **Specify the accepted encoding (contract23).** Check payload length/exact decoded length before expansion; the padded maximum is 66,666,668 characters. Recommend standard `A–Z a–z 0–9 + /`, correct optional terminal padding, zero unused bits; permit canonical unpadded lengths modulo4 of 2/3, reject remainder1, whitespace, URL-safe alphabet, percent escapes and internal/excess padding. Native `atob` alone is too permissive.
   Accept bare PNG/JPEG/WebP MIME tokens case-insensitively; data-URL header must be exactly the matching MIME plus `;base64,`, without other parameters. `data` means raw base64 only. Reject both defined sources even if equal/empty, rather than choosing truthy precedence; never rewrite stored parts. This deliberately differs from model data-first and thumbnail URL-first behavior (`packages/core/src/session.ts:510`, `packages/app/src/screens/chat/live-chat.tsx:201`).
   Validate signature/container against MIME; extension never grants support. Apply the same gate before persisted Chat thumbnail decoding (`packages/app/src/screens/chat/live-chat.tsx:199–203,348,364`), otherwise opening Chat already bypasses viewer limits. Refusal uses a text/file card, never the original URL as fallback.
4. **Pin animation scope (contract23/27/41).** Recommend static images only initially: reject APNG animation chunks and WebP animation flags/chunks by structural parsing, not substring search. A canvas pixel cap does not bound animated frame work; `<img>` can animate originals even when a bitmap probe inspected only one frame.
   An original download preserves all accepted file bytes, including EXIF/GPS/XMP; validation is not sanitization. Do not claim metadata removal or “safe file” certification. Animated originals are unavailable under the recommended first-slice policy.
5. **Enforce the claimed Chat scope.** Contract22's history read contains no Session.kind. Also use existing `api.sessions.get(sessionID)` and require `kind === "chat"`; do not infer it from a route or `ses_` prefix. No model/provider lookup is needed.
   Require one value per session/message/part parameter, exact ownership equality and correct `ses_`/`msg_`/`prt_` lowercase-hex identities. `packages/schema/src/index.ts:8–18` uses minimum-width padding, not a universal fixed-length schema. Prefix checks are routing validation, not authorization. All three absent may show Upload; partial/duplicate/malformed tuples must be unavailable. Session/history 404 is unavailable; other read failures offer Retry.
6. **Use committed dispatch, actual tuple fencing (contract34).** Replace `packages/app/src/screens/files/index.tsx:10` only for this route with a child component reading committed NavCtx; `def.render()` itself runs above that provider. Key the live viewer by the full tuple, suppress prior pixels/metadata on replacement, and independently observe actual route/tuple/preview changes.
   A live-to-live tuple change can race without a preview boundary. Invalidate GET/decode/download owners synchronously; canceled Back rearms a fresh authoritative read even if no route committed. Matching deletion must clear a still-visible outgoing viewer even when actual URL already names preview; retain its tombstone through late replies.
7. **Define download ownership, not completion fiction (contract27/33/36).** Before dispatch, freshly revalidate session existence/kind through the existing read API; after await, require unchanged actual/committed tuple, validated Blob and non-deleted owner. Known matching part changes invalidate/reload the Blob. Read failures retain Retry, never dispatch stale bytes.
   Use a separate short-lived URL for an authorized download so viewer cleanup cannot revoke it before browser handoff. Do not revoke in the click's same stack; use documented deferred cleanup and later native byte-equality verification. Renderer `<a download>` exposes no completion acknowledgement; no “saved” toast.
   Observed deletion prevents new dispatch, removes image/minimap/src/metadata/control and revokes viewer-owned URLs; revocation alone does not erase already decoded pixels. Close any stale ImageBitmap. Already-dispatched downloads, including pending save dialogs, cannot be reliably canceled by this contract; revalidation is not atomic with deletion or missed SSE.

## Minimum implementation and proof

Reuse ZoomView's controls, not its current pane-sized pan bounds/fixed3:2 minimap (`packages/app/src/screens/files/media.tsx:102–115`, `packages/app/src/screens/files/files.css:307–309`); use contained-image dimensions, ResizeObserver, Fit-relative zoom and actual aspect ratio. Keep changes live-scoped.

Optional date is message-created time, never EXIF/file-created time.
- One focused `tests/e2e/files-live.spec.ts`: real IPC-admitted PNG/JPEG/WebP, raw/data-URL and padding variants, exact duplicate-name/mismatched IDs, provider-disabled restart, keyboard/Fit/resize, native downloaded-byte equality, honest invalid/oversized/animated/source failures, no external fetch, retained dirty/refused drafts.

Header-over-limit fixtures must be rejected before the native decoder is invoked. Verify both themes/minimum and wide windows; existing preview states stay fixture-bound.
