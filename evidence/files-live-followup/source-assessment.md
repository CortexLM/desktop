Never select first file, filename, ordinal, filesystem path or latest message.
3. Support `image/png`, `image/jpeg`, `image/webp` only. Accept exactly one inline base64 `data` OR matching `data:<MIME>;base64,...` URL; reject dual/missing sources, external URLs, `file:`, caller-supplied `blob:`, HTML/SVG and arbitrary same-origin assets. Check encoded length before decoding, strict base64, MIME/signature agreement; native image decode must succeed. Apply the source restriction to clickable Chat thumbnails too.
4. Create a renderer-owned Blob URL from those validated bytes; native `<img>` decodes it. No fetch, iframe/object, HTML injection, CSS derived from filenames or filesystem reads. Render filenames as text; download basename removes path separators/control characters and uses the validated raster extension, never an untrusted executable suffix.
5. Derive byte size from decoded bytes, dimensions from successful decode, display type from validated MIME. Optional date means message attachment time, not original file creation. Reuse the existing metadata card with accurate labels; omit invented EXIF, camera/GPS, OCR and generated descriptions.

7. Download validated original Blob bytes using native `<a download>` with safe basename; no simulated success toast. Existing renderer precedent: `packages/app/src/screens/system/projects.tsx:370–373`; no save IPC exists. Recheck current owner/session before download; revoke viewer URLs on replacement/deletion/unmount, release a dispatched download's URL after handoff. Actual native completion/bytes require later verification; deletion cannot erase an already-saved download.
8. No IDs: existing Upload fallback. Missing/deleted message/part: unavailable. Unsupported source/type: unavailable. Read failure: real Retry. Decode failure: cannot-open state. Use existing kit state layouts plus Files-specific localized copy; `packages/i18n/locales/en/files.json:99–102` contains PDF-specific body/error-code text unsuitable for image failures.

## Deletion and stale ownership
- `packages/core/src/session.ts:116–127` deletes descendants/stops runs, emits deletion, rejects later history reads; `packages/core/src/storage.ts:16–18,105–108` removes message/part projections. **Journal bytes survive** (same file `:79–85,122–126`); logical removal is not secure erasure.

Guard actual navigation/preview departure and canceled Back/re-entry, not only unmount: `packages/app/src/App.tsx:20–35`, `packages/app/src/shell/shell.tsx:121` allow deferred/reused live trees. Rearm with a fresh authoritative read after canceled preview navigation.

- SSE is live-only and does not automatically reconnect (`packages/client/src/index.ts:128–140`, `packages/app/src/state/live.ts:9–12`). Do not claim absolute revocation across missed events; revalidate on re-entry/download. Local saved attachments have no remote-auth epoch; signed-in changes cannot authorize remote hydration.
