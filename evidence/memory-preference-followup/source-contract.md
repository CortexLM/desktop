## Smallest proposed runtime contract
- One engine-wide `memoryEnabled` flag, default **true only when unset**, inferred from both incumbent defaults and unconditional injection. Store one existing-table document `settings/runtime`; no schema migration/dependency/new service class. No Bot field/override: global false suppresses every existing Bot’s memory injection, including routines/children; true restores each Bot’s own notes without merging owners.
- Add shared strict schema `{ memoryEnabled: z.boolean() }`; proposed `GET/PUT /api/settings`, typed `api.settings.get/set`, inline `core.settings` beside permissionRules. PUT requires the actual boolean; reject missing/string/number/null/array/unknown fields as400/`invalid_request` before persistence. Validate in core as well as protocol. Return confirmed stored value; failed write leaves prior value/data intact.
- GET defaults only for absent document; validate persisted JSON, report malformed content as neutral500/`internal`, never silently convert corruption/read failure to true/false. Publish a small live-only `settings.changed` notification after accepted storage write; use existing bus/query mechanism for shared refresh. No arbitrary-key dictionary or new persistence framework.
- Pass resolved flag to `BotService.context`; skip memory lookup/section when off while preserving name/persona/tools/permissions. Snapshot BotContext once inside `prompt` before the first await, pass it into run instead of rereading; use that same system snapshot in admission/output budgets. A change affects future admissions, never cancels/rewrites the admitted turn, transcript or saved notes; existing history may still contain remembered information.
- Manual Add/list/export/Forget remain explicit management while off: current copy promises “no longer used”, not “no longer saved”. A newly added note stays dormant until enabled. Keep entries/IDs/times across toggle/reload; preserve caller-approved deletion semantics. Live faded rows need pointer/keyboard-consistent deletion access; a local live-only style avoids changing preview geometry.
- Bind both incumbent switches to the same engine-backed hook in `packages/app/src/state/live.ts`; preview keeps renderer state/variants. Unknown/loading/error must show loading or existing localized error+Retry, not “Memory turned off”/“remembers you”. `work.error.loadTitle/loadText`, `work.error.save`, `common.retry` already exist.
- Confirm checked/banner state only after accepted write or authoritative refresh; synchronous pending guard, disabled/busy control, stale GET/response invalidation on mutation/navigation, no duplicate requests or stale-owner toasts. Existing `useQuery:18–27` lacks unmount invalidation; do not assume it supplies mutation ownership. `kit/ui.tsx:109–110` needs narrow disabled/busy prop support for its Base UI Switch wrapper.
- Keep first-Bot management visibly scoped; do not inject `bots.data[0]` into ordinary Chat. Live-only localized descriptions must disclose Bot scope and manual Add, replacing the unsupported automatic-learning promise in both empty states; retain preview copy. This is copy/wiring work in existing components, not a new personal-memory surface.

A default-true GET alone cannot distinguish absent from explicitly true: agree the minimal absence/initialization contract first.
