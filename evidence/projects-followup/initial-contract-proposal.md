## Proposed local contract — not present at the source pin
`Project = {id,name,icon,color,instructions,time:{created,updated}}`; create `{name,icon?,color?,instructions?}`; defaults match the form; PATCH is a strict partial of these writable fields. UI editing initially covers instructions only; metadata API support is not a claim of a metadata editor.
Validate name trimmed 1–48; instructions 0–4000 (preserve newlines); exact eight-icon/six-swatch enums from `projects.tsx:15–16`; bounded nonempty IDs. Reject extra writable keys, client-supplied IDs/times, arbitrary CSS/URLs and folder/credential fields. Treat text as text, never HTML or commands.
Add `project:"prj"` to existing `newId` prefixes (`packages/schema/src/index.ts:8–18`); names may duplicate, IDs may not. `Storage.putDoc` upserts: guard generated-ID collision rather than overwrite. Explicit list order updated descending, ID tie-break independent of locale.
One `ProjectService` in `packages/core/src/project.ts`, wired before SessionService (`packages/core/src/index.ts:56–78`), using `getDoc/listDocs/putDoc/deleteDoc("project",…)` (`storage.ts:152–172`). Existing doc PK `(kind,id)` suffices; no table/migration, external database, renderer persistence or generic repository abstraction.
`Session.projectID` does **not** exist (`packages/schema/src/index.ts:142–152,459–469`). Add optional persisted ID to Session/create; PATCH accepts ID or null, null removes membership. Strictly validate existence before writing; absent field leaves membership unchanged. Session JSON/event projection already persists extra declared fields (`storage.ts:90–97`). Filter `SessionService.list` in memory; no SQL column needed for this first slice.
Membership scope: one Project per root `kind:"chat"` session; reject direct child/Code/Bot assignment. Child inference resolves its root's current project, rather than copying memberships that become stranded after a move. Refuse membership changes while that root or descendants are running/admitting (`session_busy`); project instructions are snapshotted per admitted turn, subsequent edits apply next turn.
Routes: `GET/POST /api/projects`, `GET/PATCH/DELETE /api/projects/:id`; client `api.projects.list/create/get/update/delete`; extend existing `GET /api/sessions?projectID=…`, create and PATCH contracts. No additional membership endpoint. Existing main/preload IPC and server fetch path suffice (`packages/app/src/api.ts:23–38`).
Success: list/get/PATCH 200, POST 201, DELETE 200 `{ok:true}`; existing session create 201/update 200/prompt 202 remain. Failures: 400 `invalid_request`, 404 `not_found`, 409 `conflict`/`session_busy`, 500 `internal`; existing protocol shape/status map (`packages/protocol/src/index.ts:135–172`), never raw message copy.
Use one schema event `project.changed {projectID}` after successful document commit, including deletion; `useProjects` refetches it, session events refresh membership/counts. Keep it live-only: documents are durable independently (`packages/core/src/bus.ts:12–21`, `storage.ts:25`). No new renderer store or polling.
Instructions must enter the main-owned model system context (`packages/core/src/session.ts:124–158,271–317`), not merely display in a card. Snapshot during reserved admission; include their estimated tokens in input/output budgets using existing `estimateTokens`; preserve agent/permission behavior. No history rewriting; moving/detaching changes future turns only.
Delete now: synchronous check-and-delete in `Storage.tx`; any linked root means `conflict`, with project/transcripts untouched. After explicit detach, deletion removes only the Project document and publishes after commit. Never call `SessionService.delete`: it recursively deletes children/messages (`session.ts:100–106`, `storage.ts:99–102`). Populated detach-and-delete would need an atomic event/projection design; nested `Storage.tx` plus durable `bus.publish` is invalid (`storage.ts:65–85`).
