## 1. Equal numeric IDs are distinct frames; callbacks acknowledge the preceding yield
- Vector: Redis entries `1700000000000-0` / `1700000000000-1` carry text deltas `A` / `B`; both wire IDs become `1700000000000`. Require `AB`, not `A`. Replay after that numeric cursor can repeat the `-1` entry: ID-only dedup cannot distinguish replay from a new same-ID frame.
- Backend facts: `B/server/src/chat/stream_buffer.ts:31–38,54–60,95–107` strips Redis sub-sequences and resumes with exclusive `(n-0`; `B/server/src/api/turns/emitter.ts:26–37` puts that numeric prefix on the wire.
- Cursor ordering: `next()` yielding A has not acknowledged A. Asking for the next event invokes A's cursor callback before yielding B. Equal numeric IDs still yield events but do not re-notify the SDK cursor. Breaking immediately on `done` skips its cursor acknowledgement; drain the iterator normally.
- Sources: `A/streaming.ts:945–981`; `S/stream.ts:146–156,171–191`. Resume uses decimal digits, never full Redis `n-1` IDs; SDK ignores cursor advancement for `0`, nonnumeric or non-increasing IDs. Backend parses decimal `Last-Event-ID` with `Number`: `B/server/src/api/turns/create.ts:102–108`.

## 2. Text completion does not certify generated media; post-terminal scope is narrow
- Handler-supported vector: image `queued` then image `error`, followed by the model's text/`done(stop)`. Preserve the media failure/unsupported-output notice; text success must not manufacture an image. A successful image names its stored file only after the Library/transcript writes.
- Sources: `B/server/src/api/image-gen.ts:241–269,302–335`; `B/server/src/api/chat-tools.ts:260–261`; `B/server/src/api/turns/batch.ts:271–304`; `B/server/src/api/turns/generate.ts:369–386,415–428`.
- Important pin distinction: this handler awaits image tools before `done`. The SDK additionally supports an *announced* image tail: `image_generation(generating,a), done, image_generation(done/error,a)`, including delayed chunks; multiple generation IDs settle independently. This is SDK compatibility coverage, not proof that this handler normally emits that order.
- Late-error boundary: while an announced image remains pending, a generic `error` after `done` is yielded and clears pending images. With no pending image, SDK stops at `done`; arbitrary later `error`/artifact frames are not observable. Do not demand an impossible adapter callback for that case.
- EOF/socket failure after `done` can return normally with unfinished images; SDK does not reconnect after a terminal event. Require truthful incomplete/unsupported media state, not inferred delivery. Explicit abort/account cancellation still rejects. Sources: `S/stream.ts:165–197`; `A/streaming.ts:976–1005`; source-bound archived fixture `evidence/sdk-035-admission/consumer/runtime.test.mjs:153–228`.

## 3. Ambiguous admission must retain original POST identity
- Vector: new-chat POST commits, response is successful SSE but either ID header is absent/malformed; alternatively reconnect supplies different IDs. Require admission-uncertain recovery retaining body/files/key; never a fresh-key resend or fabricated admission. Valid `x-message-id` denotes the assistant, not the local user's acknowledgement ID.
- Normal, replay and canned handlers all supply both headers: `B/server/src/api/turns/create.ts:43–44,231,243–281`; `B/server/src/api/turns/replay.ts:79`; `B/server/src/api/bounty-inject.ts:129–135`. Missing headers are a corrupted/ambiguous response, not an optional success shape.
- After receiving valid IDs then disconnecting, replay must retain `/v1/conversations/turns`, original JSON bytes and key, plus the acknowledged numeric cursor—even after learning `cnv_…`. Do not reconstruct it as the follow-up path. Snapshot before iteration as well: SDK serializes the body only when its generator first advances. Sources: `S/client.ts:306–322`; `S/stream.ts:152–170`.
- Backend mapping is **user+key**, not path/body-bound: a changed body under the same key may silently replay the old turn, not reject it. Mapping writes happen after transaction commit; failed writes are swallowed; TTL is 86,400 seconds. No exactly-once claim across lost mappings. Sources: `B/server/src/api/turns/helpers.ts:143`; `create.ts:84–108,240–258`; `replay.ts:13–37` (same directory).
- `stream_expired` is an in-band error requiring known-history recovery, never a replacement turn: `B/server/src/api/turns/replay.ts:55–68`; `S/stream.ts:189–197`.

## 4. Real PNG input, repacked metadata, separate upload/vision ceilings
- Vector: actual PNG bytes, nonempty and ≤10×1024² bytes, uploaded raw with filename. Accept a supported repacked PNG/JPEG/WebP/GIF response ≤8×1024² bytes even if filename/MIME/size differ from input. Reject larger stored metadata, unsupported stored type, or renderer-declared `image/png` whose bytes are text/PDF; retain original attachment on refusal.
- Exact caps: `B/server/src/api/media.ts:11–15`; `B/server/src/api/library/index.ts:309–330,342–382`. Repacking can change all three metadata fields: `B/server/src/api/media.ts:121–141`. There is no 1 MiB minimum; ≤10 MiB ingest does not establish ≤8 MiB vision suitability.
- Backend sniffs bytes, not the request Content-Type/extension: `B/server/src/tools/artifacts.ts:120–143,207–220`. Unsupported stored MIME or oversize stored/actual bytes are silently skipped by vision: `B/server/src/api/library/index.ts:635–658`; MIME-only acceptance loses the image.
- Use a genuine image fixture: the ten-byte signature in `evidence/sdk-035-admission/consumer/consumer-check.mjs:9–23` proves raw transport only, not image validity. Backend signature sniffing is not full decoding; failed image decoding can leave bytes unchanged (`B/server/src/api/media.ts:49–59,77–83,121–124`). Upload ownership stays epoch-bound; backend independently checks owner (`B/server/src/api/library/index.ts:611–630`).

## 5. Clock expiry without state polling; 401 ownership; native auth single-read
- Vector: obtain a valid local session/binding at `expires_at - 1ms`; advance to exactly `expires_at` without calling `state()`. Exercise a cached binding operation, a deferred response and an SSE callback. Require expiry detection at binding/request/callback boundaries, epoch invalidation and suppression of late results; identity equality alone is insufficient.
- Backend issues explicit local `expires_at` and rejects at equality: `B/server/src/api/self-host.ts:71–91`; `B/server/src/auth/local.ts:31–47`; `B/server/src/http/principal.ts:120–128`. SDK checks token-source changes/abort signals, not that timestamp: `S/client.ts:130–143,145–152,251–260`. Cloud auth does not supply this expiry (`B/server/src/api/auth.ts:174–178`); do not infer it from an unverified JWT.
- Separate 401 vector: no refresh callback, pending request returns 401 with arbitrary/malformed body. Main must invalidate the active epoch; SDK simply returns 401 without refreshing (`S/client.ts:196–210`). Turn `onResponse` never sees that response: HTTP failure is thrown before the callback (`S/stream.ts:137–143,169–170`). Late success from an aborted account must not merge cookies (`S/client.ts:168–181`).
- Native auth guard: successful non-bodyless auth JSON uses one `arrayBuffer()` then detached `Response`, not `Response.clone()` (`S/client.ts:155–166`). Preserve main's bounded auth transport; do not apply its whole-body buffering policy to SSE. Expected binding policy: `evidence/remote-auth-followup/routing-contract/README.md:32–34,44–48,77`.
