## Exact byte/text policy
- Accept only bare case-insensitive `text/plain`/`text/markdown`; exactly one defined raw-base64 `data` OR matching `data:<MIME>;base64,` URL. Refuse both/neither, charset parameters, external/file/arbitrary blob URLs and extension-based guesses. Markdown displays source, not rendered links/HTML.
- Recommend inclusive **5,000,000 file bytes**; check encoded length (maximum 6,666,668) and exact decoded length before allocation. Reuse canonical standard-base64 rules, including zero pad bits and allowed unpadded tails; explicitly accept `data:""`/empty data-URL payload. Raster's current `length > 0` check must remain raster-specific.
- Decode with `TextDecoder("utf-8", { fatal: true })`; default BOM handling removes one leading UTF-8 BOM from display/Copy. Record BOM presence from bytes, retain original bytes for download. Reject malformed/overlong/truncated UTF-8 and UTF-16 BOMs; no encoding fallback or reliable detection claim for unmarked bytes valid in multiple encodings.
- Refuse NUL and C0 controls other than HT/LF/CR, plus DEL, as an explicit unsupported-text policy; no complete binary detector or sanitization claim. Preserve other Unicode, tabs, whitespace and original CR/LF sequences in the decoded Copy string.
- Define logical display rows explicitly: empty decoded text = 0; otherwise `1 + count(/\r\n|\r|\n/g)`, including a trailing empty row (`"a\r\n"` = 2, `"\r"` = 2). CRLF counts once. Normalize breaks only for visual row layout; original decoded text/bytes remain separate.
- Recommend additional inclusive **50,000 display rows / 100,000 UTF-16 units per row**, counted before splitting/rendering; refuse excess honestly, never truncate. These permit simple native scrolling without millions of gutter/minimap nodes; no IPC/history/total-memory bound or virtualization commitment.
